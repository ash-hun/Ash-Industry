## 화면 목록

경로 알파벳순.

| 경로 | 화면 | 목적 | 상태 |
|---|---|---|---|
| `/` | HUD | 에이전트와 대화하고 옆 카드로 상태를 본다 | 구현됨 |
| `/` (FLOW) | Workflow | 에이전트 사이 위임과 백그라운드 작업을 본다 | 구현됨 |
| `/` (SET) | Settings | 설정을 보고 허용 목록 안의 값을 고친다. 데스크톱 앱이면 앱 설정도 | 구현됨 |
| `desktop/loading.html` | 부팅 화면 | 앱을 켜면 로고와 부팅 로그, 백엔드가 응답하면 SYSTEM ONLINE 뒤 HUD 로. 없으면 띄우는 방법 | 구현됨 |

경로는 하나고, 화면 셋(HUD, FLOW, SET)은 헤더 오른쪽 탭으로 바꾼다(`body[data-view]`, 고른 화면은 localStorage `hud.view`). 바꿀 때 지금 화면의 카드가 반대쪽으로 살짝 물러났다가 화면 밖으로 빠지고(HUD 는 왼쪽 열은 왼쪽, 오른쪽 열은 오른쪽, 리액터는 안으로 접힌다), 다음 화면의 카드가 반대편에서 차례로(45ms 간격) 밀려 들어와 조금 지나쳤다가 두 번에 걸쳐 제자리에 걸린다(나가기 240ms, 들어오기 420ms). 탭 밑줄 하나가 고른 탭으로 미끄러져 간다. 움직이는 동안 누른 탭은 마지막 것 하나만 끝난 뒤에 간다. 움직임 줄이기 설정이면 바로 바뀌고, 처음 열 때는 움직이지 않는다. 세션 전환은 URL 이 아니라 WebSocket 재연결로 한다. 그 외 경로는 nginx 가 `index.html` 로 돌려준다.

## 화면별 상세

### `/` HUD

**목적**: 가운데 리액터를 중심으로, 왼쪽에 에이전트 상태 카드, 오른쪽에 세션과 대화를 둔다. 접속하면 바로 `default` 세션(main)에 붙는다. 화면의 이름, 명언, 색(링, 구체, CSS 변수)은 지금 세션 에이전트의 것이다.

**레이아웃**: 헤더, 3열 스테이지, 하단 입력 독.

```
┌──────────────────────────────────────────────────────────────┐
│ [≡]              ● A.S.H.                     HUD  FLOW  SET  │ 헤더
│                  2026.11.03 TUE 13:14:57                     │
├───────────────┬──────────────────────────┬───────────────────┤
│ AGENDA        │                          │ SESSIONS        + │
│  UPCOMING     │    ‹   리액터(구체)   ›   │  default  NOW ⑂   │
│  OPEN LOOPS   │                          │                   │
├───────────────┤       ● ACTIVE           ├───────────────────┤
│ ACTIVITY      │       "명언" / 마지막 줄  │ CONVERSATION      │
│               │                          │  USER / A.S.H.     │
│               │                          │  💭  SYS          │
├───────────────┴──────────────────────────┴───────────────────┤
│ 📎 >_ [입력창                    ]  [AUTO] [SEND ⏎]          │ 입력 독
└──────────────────────────────────────────────────────────────┘
```

헤더 가운데 묶음(연결 점, 이름, 그 밑의 날짜와 요일과 시각)은 창 가운데가 아니라 리액터 구체의 가로 중심에 맞춘다(`header.js`). 좌우 카드 열 폭이 달라 둘이 어긋나기 때문이다. 연결 점은 이름 왼쪽에 띄워 두어 이름 글자만으로 가운데를 맞춘다. 오른쪽은 화면 탭(밑줄)이고, 왼쪽 ≡ 버튼은 860px 이하에서만 보인다. 헤더에 상태 글(READY 등), 버전, 음성 모드 버튼은 없다. 지금 무엇을 하는지는 리액터 아래 상태 줄이 보인다.

헤더 바로 아래 ION 띠는 플랫폼 감시(Ion)가 연 사고가 있을 때만 나타난다(붉은 기운의 한 줄, `ION` 표식). 사고마다 제목, 상세, 버튼(첫 버튼이 추천, 붉은 테두리)이 한 줄이고, 답하면 버튼 대신 `재기동 · 재기동함` 같은 결과가 8초 보였다가 사라진다. 이 띠는 `/ion/` 로 Ion 컨테이너에 붙어 백엔드 ws 가 끊겨도 산다. 열린 사고가 있는 동안 리액터 구체 뒤 배경이 가장 심한 등급의 색으로 물든다(critical 은 붉은색, warning 은 주황색. `body[data-ion]`). 사고는 띠와 함께 지금 보고 있는 대화(어느 에이전트의 세션이든)에 `ION` 카드로 끼어든다. 카드는 띠와 같은 줄(제목, 상세, 버튼)이고 답하면 결과가, 신호가 사라지면 `해결됨` 이 남는다. 세션을 바꾸면 열린 사고 카드가 새 대화에 다시 끼어든다. 카드는 화면에만 있고 저장되지 않는다.

열 안은 세로 flex 다. 카드를 접으면 아래 카드가 그 자리를 채운다. ACTIVITY 는 최소 96px 를 지킨다. 860px 이하에서는 왼쪽 열이 드로어가 되고(헤더의 ≡ 버튼), 리액터 아래에 SESSIONS 와 CONVERSATION 이 온다.

**Focus 레이아웃** (`body[data-focus="on"]`, `/focus <작업>` 동안):

```
┌──────────────────────────────────────────────────────────────┐
│                  ● A.S.H. [FOCUS]               HUD FLOW SET  │
├─┬──────────────────────┬───────────┬───────────────────────┬─┤
│A│ REFERENCE  조사 및 종합│  ╭─────╮  │ ANALYSIS 목적, 필요…   │S│
│G│  선례, 출처, 적용할 점 │ (  구체  ) │  근본 목적 … 미리 대비 │E│
│E│                      │  ╰─────╯  │                       │S│
│N├──────────────────────┤  ● ACTIVE ├───────────────────────┼─┤
│D│ LOG  작업 기록         │           │ PROGRESS        경과   │C│
│A│  시각별 3인칭 기록     │           │  33%       약 21분 남음│O│
│…│                      │           │  ✓ 단계 ○ 단계         │N│
├─┴──────────────────────┴───────────┴───────────────────────┴─┤
│ 📎 >_ [입력창                           ]  [SEND ⏎]          │
└──────────────────────────────────────────────────────────────┘
```

좌우 카드는 머리글만 세로로 세운 30px 띠가 된다. 구체는 70% 크기에 채도와 밝기가 오르고, 둘레에 네 영역 쪽으로 뻗는 호가 그려진다. 들어갈 때는 띠 접힘, 구체 축소, 호, 네 영역 순으로 약 1.2초, 나올 때는 거꾸로 간다. 아래 줄(LOG, PROGRESS)은 내용 높이만큼(최소 30%, 최대 50%)이고 남는 높이는 위 줄이 갖는다. LOG 바닥에 `기록 N건 · 마지막 HH:MM`, PROGRESS 바닥에 `단계 완료/전체 · 갱신 HH:MM` 한 줄이 붙는다. 구체 아래 캡션은 가운데 빈 칸(구체 폭의 절반) 안의 한 줄로 줄고, 마크다운 기호와 반쯤 온 링크를 걷어 낸 글자만 보인다. 응답이 나오는 동안 CONVERSATION 띠가 숨쉬듯 빛난다(펼쳐 두면 빛나지 않는다). 860px 이하에서는 구체 아래로 PROGRESS, REFERENCE, ANALYSIS, LOG 를 쌓고 맨 아래에 CONVERSATION 막대만 둔다.

**에러 상태**

WS 끊김: 헤더 이름 옆 점이 빨갛게 멈추고, 헤더 바로 밑에 배너 `연결 끊김 — 재연결 중...`, 입력 잠금, 1초부터 2배씩 최대 10초 간격으로 재접속. `4401` 이나 REST `401`: 접근 키 창(비밀번호 입력칸, 저장과 취소. STT 오류: SYS `STT 오류: …`, 인식한 글이 비면 SYS `음성을 인식하지 못했습니다.`. `4404`(모르는 에이전트): 재접속하지 않는다. ACTIVITY `에이전트 없음 · <세션> · <이유>` 를 남기고, 보던 세션이 `default` 가 아니면 `default` 로 한 번 옮겨 붙는다. `default` 도 4404 면 배너만 남기고 멈춘다. 승인 요청 120초 무응답: 서버가 거부로 처리하고 도구 결과에 `denied` 가 온다. 다른 에이전트를 보는 동안의 요청도 같은 120초다(띠를 눌러 돌아오면 답할 수 있다). 음성 TTS 오류: `error` 로 와서 음성 상태가 풀린다.

**인터랙션**: 그래프는 휠로 확대, 축소하고 빈 곳을 끌어 옮긴다(`−`, `+`, `맞춤` 버튼도). 노드는 끌거나 방향키로 옮기고 `정렬 최적화`, `원래대로` 버튼이 있다(데이터 표). 에이전트 허브에 마우스를 올리면 그 에이전트에 닿은 잎, 공통 능력 상자, 간선만 밝게 남고 나머지는 흐려진다. 노드에 올리면 패널 안 말풍선에 이름(도구는 승인 필요 여부와 공통 주인까지)과 설명 한 줄. 간선에 올리면 `이름 → 이름 · N회`. 지도의 `ask` 카드는 누르거나(Enter, Space) 받는 쪽 세션(`peer-…`)으로 바로 전환한다(`session:open` 이벤트, `session.js` 가 받는다). 카드에 올리면 경로, 종류, 시작 시각, 맡긴 일 전문이 제목으로. `Esc` 는 HUD 로 돌아간다(입력 중이 아닐 때).

**빈 상태**: 위임이 없으면 그래프에 에이전트 노드만, 지도는 뿌리 카드와 `이 세션에서 나간 위임이 아직 없습니다`. 작업이 없으면 머리줄 `작업 없음`, 펼치면 `등록된 백그라운드 작업이 없습니다`.

**에러 상태**: REST 실패는 이전 값을 그대로 두고 다음에 화면을 열 때 다시 받는다. 서버가 재시작되면 그래프와 실행 횟수가 비어 다시 쌓인다(postgres 백엔드면 지도의 지난 위임은 남는다).

### `/` SET — Settings

**목적**: 지금 적용된 설정을 보고, 화면에서 고쳐도 안전한 값(voice, proactive, thought, focus 의 일부와 HUD 단축키)을 저장한다. 데스크톱 앱이면 단축키와 자동 실행 같은 앱 설정도 여기서 고친다.

**레이아웃**: 왼쪽 열에 SYSTEM 과 DESKTOP(데스크톱 앱에서만), 오른쪽 열(2배 폭)에 SETTINGS, 그 아래 줄 전체에 MCP(MCP 서버가 있을 때만), 맨 아래 줄 전체에 EFFECTIVE CONFIG. 860px 이하에서는 한 열로 SYSTEM, SETTINGS, DESKTOP, MCP, EFFECTIVE CONFIG 순. SYSTEM 은 HUD 왼쪽 열에 있던 카드를 그대로 옮긴 것이다(가동 시간, 모델, 세션, 토큰, 비용, 사용량 그래프, TOOLS 목록).

```
┌──────────────────────────────────────────────────────────────┐
│ 헤더                                          HUD  FLOW  SET  │
├────────────────────┬─────────────────────────────────────────┤
│ SYSTEM    00:12:04 │ SETTINGS        ~/.ash/settings.yaml │
│  MODEL   gpt-4o    │ VOICE                                   │
│  TOKENS…COST       │  Stt Provider    [browser ▾]            │
│  TOOLS ▾           │  Wake Threshold  [0.5     ]             │
├────────────────────┤ PROACTIVE …                             │
│ DESKTOP    앱 전용 │ 단축키  듣기 시작/토글 [Ctrl+Shift+Enter] │
│ 전역 단축키 [ … ]   │ 저장됨 · 재시작하면 반영 [RESTART] [SAVE] │
│ 백엔드 주소 [ … ]   │                                         │
├────────────────────┴─────────────────────────────────────────┤
│ EFFECTIVE CONFIG                                  비밀값 ***  │
│ { "llm": { "provider": "anthropic", "api_key": "***", … } }   │
└──────────────────────────────────────────────────────────────┘
```

**데이터**: 폼은 `GET /api/settings` 의 `fields`(형식, 선택지, 범위)로 그리고 값은 `pending` 이 있으면 그 값, 없으면 `editable`. 선택지가 있으면 select, boolean 은 체크박스, 숫자는 범위가 걸린 number, 문자열은 pattern 이 걸린 text. 단축키 묶음(`shortcuts`)은 legend `단축키` 아래 형식 안내 한 줄(`Ctrl`, `Alt`, `Shift`, `Meta` 를 `+` 로 잇고 끝에 키 이름, macOS 의 Ctrl 은 Control 키, Cmd 는 Meta)과 네 칸(듣기 시작/토글, 읽기 멈춤, 이전 에이전트, 다음 에이전트). 키를 눌러 기록하는 입력은 없고 글로 쓴다. DESKTOP 은 `window.ashDesktop.getSettings()`.

**상태와 파라미터**: 저장 직후 상태 줄은 응답대로 셋 중 하나다. 바로 쓴 키가 있으면 `반영됨 · voice.wake_threshold, …`(강조색), 바로 쓸 수 없는 키가 있으면(`restart_required`) `저장됨 · thought.enabled 은 백엔드를 다시 띄우면 반영됩니다`(경고색), 바뀐 게 없으면 `바뀐 값이 없습니다`. `pending` 에 든 행(재시작해야 반영되는 키)은 이름 뒤에 `· 재시작 대기`. 화면을 다시 열어 대기 항목이 있으면 상태 줄 `저장됨 · 백엔드를 다시 띄우면 반영됩니다`. 대기 항목이 있을 때만 RESTART BACKEND 버튼이 보인다(브라우저와 데스크톱 앱 모두).

**인터랙션**: SAVE 는 적용값과 다른 값만 `PUT /api/settings` 로 보내고 서버가 바로 반영한다. 바뀐 것이 없으면 `바뀐 값이 없습니다`. 응답의 `applied` 에 `voice.` 키가 있으면 ws 를 다시 붙인다(접속 인사가 음성 모드와 언어를 정하므로, 대화 화면이 새로 그려진다). 응답(과 SET 을 열 때 읽은 값)의 `editable.shortcuts` 는 이 창의 단축키에 바로 쓴다. 다른 창은 새로 고치거나 SET 을 열 때 바뀐다. RESTART BACKEND 는 누르는 즉시 헤더 연결 점을 `연결 끊김 — 재시작 중` 으로 바꾸고 `POST /ion/restart` 로 Ion 이 컨테이너를 재기동하게 한다. Ion 이 없거나 거절하면 활동 로그에 `ion restart 실패 (<이유>) · 백엔드 자기 재시작으로` 를 남기고 `POST /api/restart` 를 부른다(백엔드가 스스로 종료해 Docker restart 정책으로 다시 뜬다). 받아들여지면 상태 줄 `재시작 중 · 연결이 돌아오면 다시 붙습니다`, 서버가 보낸 `restarting` 이벤트로 열린 HUD 전부가 같은 연결 표시를 보이고, 소켓이 닫히면 기존 재접속 루프가 돌아온 뒤 다시 붙는다. 데스크톱 앱은 페이지를 다시 읽는다. DESKTOP 의 SAVE 는 셸이 검증해 저장하고 단축키와 자동 실행을 바로 적용한다.

**빈 상태**: 브라우저에서는 DESKTOP 카드가 없다.

**에러 상태**: 형식이나 범위가 틀린 칸이 있으면 저장하지 않고 `범위나 형식이 맞지 않는 값이 있습니다` 와 함께 그 칸으로 간다. 서버 422 면 서버가 준 이유를 칸 이름과 함께 `저장 실패 · shortcuts: 단축키가 겹칩니다: voice_stop 와 agent_prev 이 모두 Escape` 처럼, 이유가 없는 실패는 `저장 실패 (코드)`, 연결이 없으면 `백엔드에 연결되지 않았습니다`. 데스크톱 설정이 틀리면(루프백이 아닌 주소, 등록할 수 없는 단축키) 셸이 거절한 이유를 보인다. Ion 과 백엔드 자기 재시작이 둘 다 안 되면(컨테이너 밖이면 `no supervisor`) 연결 점을 되돌리고 `재시작 실패: <이유>. docker compose restart ash-backend 를 직접 실행하세요`.


**AUTO MODE 카드**(`GET /api/auto-approve`): 최상위 에이전트마다 체크박스(`<이름> (<id>)`). 바꾸면 `PUT /api/auto-approve/{agent}` 로 바로 저장한다. 카드 위 안내: 켜진 에이전트는 쓰기 도구와 MCP ask 도구를 묻지 않고 실행하고, 위험 명령, MCP deny, never 는 막으며, 무인 실행에는 적용하지 않는다.

**MCP 카드**(`mcp_servers` 가 있을 때만, `GET /api/mcp/policy`, `GET /api/mcp/audit`):

| 요소 | 동작 |
|---|---|
| 종류별 기본(읽기, 쓰기, 모름) | allow, ask, deny 셀렉트. 도구에 모드가 없을 때 쓰는 값 |
| 판정 기준 에이전트 | `main`, 팀 에이전트(`/api/agents`), 정책의 `agents` 키 중 하나. 바꾸면 `GET /api/mcp/policy?agent=<id>` 로 표의 판정을 다시 받는다. SAVE 응답도 이 에이전트 기준 |
| 도구 표 | 서버, 도구(설명은 `title`), 종류, 모드(기본, allow, ask, deny), 시간당 상한(빈칸이면 없음), 인자 고정(`to=a@x.com|b@x.com; cc=c@x.com` 꼴), 판정(서버가 계산한 지금 모드. deny 는 빨강, ask 는 주황) |
| SAVE | 표 전체를 정책 문서로 만들어 `PUT /api/mcp/policy`. 성공하면 `저장됨 · 바로 적용` 과 새 판정. 422 면 `저장 실패 (422)` |
| MCP CALLS | 최근 50건, 최신이 위. 시각, 판정(에이전트 allow, ask, deny) 또는 결과(성공, 실패), 호출 요약과 이유 |

### `desktop/loading.html` — 부팅 화면

**목적**: 데스크톱 앱을 켜면 Ash 심볼과 부팅 로그를 보이고, 백엔드(`/api/health`)가 응답하면 `SYSTEM ONLINE` 을 띄운 뒤 HUD 로 넘어간다. 앱은 백엔드를 띄우지 않는다.

**상태**

| 상태 | 화면 |
|---|---|
| `shell` | 인라인 SVG 심볼이 나타나고 가운데 주황 코어가 빛난다. 부팅 로그 첫 줄(셸 시작) |
| `connecting` | 로그에 백엔드 연결 줄. 링이 돈다 |
| `online` | 로그에 백엔드 응답 줄과 `SYSTEM ONLINE`. 처음 뜬 뒤 2초가 될 때까지 머문다 |
| `exit` | 0.6초 동안 어두워지고 HUD 를 연다 |
| 오류(`?error=`) | 링이 멈춰 빨갛게 되고 코어도 빨갛다. `백엔드(주소)가 응답하지 않습니다. docker compose --profile web up -d 로 띄우면 자동으로 연결합니다.` 를 글로만 보인다. 5초마다 다시 보다가 응답하면 `online` 으로 바뀐다 |

로그 줄은 앞으로만 늘어 같은 단계가 두 번 와도 줄이 늘지 않는다. 움직임 줄이기 설정이면 애니메이션과 기다림 없이 바로 넘어간다. 위쪽 52px 띠를 잡고 창을 끈다. 글은 모두 `textContent` 로 넣고 CSP 는 `default-src 'none'`(인라인 스타일과 스크립트만)이다.

## 미구현 / 알려진 제약

- 음성 승인 답은 부정어가 있으면 분류 없이 거부한다. "허용 안 해" 처럼 긍정과 부정이 섞인 말은 늘 거부다.
- 웨이크워드가 켜져 있으면 대기 중에도 마이크를 계속 열어 두므로 녹음 표시가 꺼지지 않는다. 마이크를 닫으려면 `ASH_VOICE__WAKE_MODEL_DIR` 를 비운다.
- 음성 대화의 자동 듣기는 읽기가 끝날 때마다 한 번이다. 말이 없으면 대화가 끝나고, 다시 시작하려면 웨이크워드를 부르거나(켜져 있을 때) 구체를 누른다.
- 웨이크워드는 Chrome 처럼 16kHz AudioContext 에 마이크를 바로 이을 수 있는 브라우저에서만 돈다. 안 되면 ACTIVITY 에 `wake word off · <이유>` 를 남기고 끈다.
- 웨이크워드 모델은 합성 음성으로만 학습했다. "Jars", "Garbage" 처럼 비슷한 소리에 깨어날 수 있고, 한국어 발음 "자비스" 는 알아듣지 못한다.
- 읽기 문구는 다른 읽기와 겹칠 수 있다(도구 시작 문구를 읽는 중에 💬 filler 문구가 오면 둘 다 소리 난다).
- 읽기가 겹치면(💬 filler 를 읽는 중에 승인 요청이 오면) 소리가 겹치고, 먼저 끝난 쪽에서 듣기가 시작될 수 있다.
- Focus 동안 🔔(먼저 건네는 말)는 서버가 보내지 않는다. 💬 filler 와 맡긴 일의 답은 그대로 온다.
- Focus 의 진행률은 진행 sub-agent 가 매긴 단계 완료로 계산한다. 단계를 늘리면 퍼센트가 내려간다. 예상 시간은 지금까지 걸린 시간 / 완료 단계 수 × 남은 단계 수라, 완료 단계가 없으면 `예상 시간 계산 중` 이다.
- Focus 의 분석은 지시가 들어올 때 메인 응답과 같이 돈다. 그 결과는 이번 응답이 아니라 다음 응답의 시스템 프롬프트에 들어간다(첫 지시만 시작할 때 기다려서 첫 응답에 넣는다).
- 세션 목록은 프로세스가 띄운 것만 보인다. 저장소에만 있는 세션은 화면에 없다.
- Postgres 저장소에서 ⑂ 분기는 빈 새 세션이다. 히스토리가 복사되지 않는다.
- open loop 중복 판정은 정규화 일치, 포함 관계(6자 이상), 임베딩 코사인 0.85 이상(`ASH_MEMORY__EMBEDDING_*` 설정이 있을 때), 글자 bigram 겹침(Jaccard 0.4 이상)이다. 뜻이 멀게 바꾼 약속("운동 등록" 과 "헬스장 회원권")은 따로 쌓인다.
- open loop 는 ✓ / ✕ 말고도, 대화에서 끝났거나 취소됐다고 AGENDA 판단이 판단하면 done 으로, 사용자가 취소하는 말로 가리키면 dismissed 로, 기한이 지나면 expired 로 저절로 닫혀 Open loops 에서 빠진다. 잘못 닫힌 것은 Closed 에서 ↺ 로 되살린다. Closed 는 최근 10개만 보인다.
- 사용자 입력과 글자가 거의 겹치지 않는 새 약속은 저장하지 않는다. 입력과 전혀 다른 말로 바꿔 적은 약속은 AGENDA 에 오지 않는다.
- 구체 색 섞기는 두 색까지다. 세 에이전트가 함께 일해도 앞의 두 색만 섞인다. 링과 패널 색은 지금 에이전트 그대로다.
- 에이전트끼리의 대화(`peer-<부른 쪽>-<받는 쪽>` 세션)는 세션 목록에 다른 세션처럼 보인다. 눌러서 받는 쪽 대화를 볼 수 있다.
- AGENDA, ACTIVITY, SESSIONS 는 지금 보는 에이전트의 것만 보인다. 모든 에이전트를 한꺼번에 보는 보기는 없다(FLOW 의 그래프와 작업 표가 전체를 보인다). ACTIVITY 는 화면을 새로 고치면 비고, 다른 화면(창)에서 생긴 일은 그 화면에만 남는다.
- open loop 는 닫기와 되살리기만 되고 수정은 없다. 스케줄은 켜고 끄기만 되고 만들기와 지우기는 슬래시 명령(`/schedule`)으로.
- 음성 TTS 요청에 서버가 응답하지 않으면 `음성 처리 중` 상태에 머문다(서버가 빈 `voice_tts_audio` 를 돌려주는 것으로 막고 있다).
- 오른쪽 아티팩트 패널은 응답 하나에 코드블록 하나만 보여준다(가장 긴 것).
- 입력창은 한 줄이다. 줄바꿈 입력 없음.
- Electron 의 브라우저 음성 인식은 Google 키가 없어 `network` 오류로 끝난다. 이때 서버 STT(`voice.stt_fallback`)가 있으면 그 연결이 끝날 때까지 녹음을 서버로 보내 받아 적고 ACTIVITY 에 `voice · 브라우저 인식 불가(network) → 서버 인식` 을 남긴다. 재접속하면 브라우저 인식부터 다시 시도한다.
- 데스크톱 앱에서는 Web Push(서비스 워커)가 돌지 않는다. 앱이 트레이에 떠 있는 동안만 OS 알림이 온다.
- Workflow 그래프의 기본 배치는 부채꼴이라 노드가 많으면 이름이 겹친다. `정렬 최적화` 로 밀어내거나 끌어서 옮긴다. 옮긴 자리는 브라우저마다 따로다.
- router 를 켜면 direct 로 판정된 요청은 사고하지 않는다. 그 턴에는 💭 줄, 💬 filler 가 없다. think 로 판정된 요청의 사고는 응답과 함께 돌아 💭 줄이 응답 뒤에 오고, 그 해석은 이번 응답이 아니라 다음 응답에 쓰인다. 응답이 사고를 기다리지 않으므로 think 턴에도 💬 filler 는 나오지 않는다.
